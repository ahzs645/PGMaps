# LiDAR model comparison workspace

`/dev/lidar/compare/` brings the executed tree-model variants into the existing map interface. The workspace has its own fixed-height shell, scrollable catalogue and results areas, two map panes and a shared vector/satellite/none basemap selector. It does not embed an external app or iframe.

- **LiDAR segmentation:** compare saved watershed, Dalponte 2016, Li 2012 and PointTree treeX results on three identical buffered plots. Full-input counts, unassigned returns, recorded runtime/RSS and adjusted Rand disagreement accompany the same deterministic display sample. Camera linking and equal-metre side profiles support inspection. A zero-instance treeX run is retained as a completed result, not replaced by another method. Agreement, coverage and counts are not accuracy, and watershed membership-lookup timing does not measure a fresh watershed run.
- **RGB crowns:** DeepForest boxes and CanopyRS Mask R-CNN masks are rendered over their actual OSBS/SJER image locations. The TIFF pixels were verified identical to each inference image before accepting its georeferencing. This is US sample imagery, not the BC LiDAR tile. Users can change the confidence threshold, toggle mask/box display and reference outlines, link cameras and inspect box-match diagnostics. These are development fixtures, not independent validation or 3D point labels.
- **3D shape review:** five complete original-return crops show how tree-shaped crowns differ from structure-shaped and low-vegetation selections. No neural segmentation or verified species/structure classification is claimed.
- **Model catalogue:** all researched variants have an explicit completed, blocked, unreleased or not-run status. Selecting an unavailable model unmounts existing output panes and shows the actual blocker; no old map, invented prediction or zero-valued performance score is presented as its result.
- **User decisions:** dataset-scoped local preferences and notes can be saved and exported with inputs, labels/boxes, parameters and provenance. LiDAR exports contain the saved display-sample labels; the underlying processing used the full accepted plots. Local preferences are not field validation.

Modules are under `src/pages/dev-lidar/comparisons/`. `ComparisonMap.tsx` owns MapLibre lifecycle, relative camera synchronisation, raster/GeoJSON overlays and the existing original-point custom layer. Family-specific components own their selectors and metrics; registry, data verification, RGB box matching and preferences are separate modules. Existing tree benchmark adapters are reused.

`scripts/lidar/build_model_comparison.py` packages already executed outputs and original crops; it does not rerun models. It verifies original result/image/reference hashes and PNG/TIFF pixel identity, retains checkpoint/source hashes and generates geographic display contours from the saved binary masks. Very small contours are omitted from display only; diagnostic box metrics retain the original boxes. Rebuild with the existing local experiment and crop paths, or supply them using `--experiments`, `--crops` and `--output`.

Tests compare browser-side box matching to all four recorded Python runs, check georeferencing and masks, reject source mismatches, exercise variant/dataset/status changes and verify scoped preference export. Camera numerical echo suppression is checked separately. Browser/WebGL visual QA is not claimed when the browser connection is unavailable.

The separate [forest volume workspace](research/lidar-forest-volume.md) adds calibration-ready m³/ha modelling and explicit harvest scenarios. Species and building reconstruction remain linked to their existing dedicated workspaces.
